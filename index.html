안내 REBOOT는 실제 기업 알디콤을 모티브로 팀이 제안한 가상 브랜드이며, 화면 속 주문 · 매출은 시연용 데이터입니다.

문제와 해결

문제 01 · 규제 표현

효능을 말하기 어려운 시장

미국 FDA는 숙취 ‘예방 · 치료 · 완화’ 같은 표현을 문제 삼습니다. 팀 조사에서 2020년 숙취 제품 경고장 7건을 확인했습니다.

해결 · 광고 문구 점검

경고장의 문제 표현 53개를 규칙 13개로 정리해 상세페이지 · 챗봇 답변 · 광고 문구를 1차 점검합니다. 법적 적합성을 보장하는 기능이 아니며, 최종 판단은 담당자가 합니다.

문제 02 · 낮은 인지도

좁은 판매 접점

Weee! · Yamibuy 같은 아시아계 채널 위주라 일반 미국 소비자에게 브랜드와 카테고리가 낯섭니다.

해결 · 브랜드 사이트 · 크리에이터 링크

효능 대신 맛과 포맷을 내세운 브랜드 사이트와 자사몰. 크리에이터별 전용 링크 · 할인코드로 SNS 유입부터 주문까지 추적합니다.

문제 03 · 운영 인력 부족

1명이 5개 채널 운영

해외 담당자 한 명이 Amazon · Weee! · Yamibuy · TikTok · Instagram을 맡아 카피 작성 · 규제 확인 · 채널별 재작성에 시간이 몰립니다.

해결 · 마케팅 대시보드

하루 업무 순서대로 메뉴 8개 — 현황 확인 · 콘텐츠 제작 · 광고 문구 심의 · 인플루언서 · 고객 응대 · 성과 분석을 한곳에서.

문제 정의 출처: 팀 「미국 숙취해소제 시장 타당성 분석」

현업 도입을 고려해 안전장치를 설계했습니다
  • AI는 초안만저장은 관리자 확인 후
  • 개인정보 가림이메일 · 전화번호 마스킹
  • 권한 확인시스템 간 API는 토큰 인증
  • 비밀정보 분리API 키는 별도 설정 파일(.env)
  • 비용 통제견적 확인 후 생성 · 10분당 40건 제한
  • 업로드 검증JPG · PNG · WEBP만 허용
협업 방식 상세 · Git 규칙과 문서화
  • 브랜치 전략feature/이니셜-기능명 → dev로 PR → 확인 후 main 병합. 서버는 main만 배포
  • 충돌 방지파트별 폴더 · DB 테이블 · CSS 클래스에 접두사, 자기 폴더만 수정, 공통 파일은 PR에 [공통] 표시
  • 한 PR = 한 파트파트 간 의존 순서(공통 → 모델 → 관리자)를 README에 정해 병합 순서를 맞춤
  • 보안.env · DB 파일은 Git에서 제외하고 .env.example만 공유
  • 두 저장소 연결브랜드 사이트와 대시보드는 저장소를 나누고, 토큰 인증 API로만 데이터를 주고받음
